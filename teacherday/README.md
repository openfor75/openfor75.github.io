# 誰能把禮物送進老師ㄉ心裡｜線上商城

115學年度 教師節限定商品模擬市場｜國立員林家商 商貿科（商業經營科・國際貿易科）

老師登入後看到自己的商貿幣（✨）餘額，逛型錄、下訂、可取消；
主辦單位輸入管理密碼後多一個「後台結算」分頁，直接算出購買數量、銷售額、銷貨成本、毛利、毛利率與三座冠軍。

```bash
pip install -r requirements.txt
streamlit run app.py
```

沒有設定 Google 試算表時，程式會直接讀寫 `data/` 底下的四個 CSV，
可以先用附的示範資料把流程走一遍。測試帳號：**林亭妤 / 1234**、管理密碼 **bae2026**。

## 二、正式上線：改用 Google 試算表存資料

Streamlit 免費主機重開機會把檔案清空，正式開賣一定要接試算表。

### 1. 開一份 Google 試算表，建立四張分頁

**分頁一：商品**

| 商品ID | 班級 | 商品名稱 | 售價 | 單位成本 | 商品介紹 | 示意圖 | 上架 |
|---|---|---|---|---|---|---|---|
| P01 | 商一甲 | 撐住老師咖啡包 | 120 | 59.80 | 50字以內介紹 | 圖片網址 | 是 |

- `上架` 欄填「是」才會出現在型錄，資格審查沒過的先留空。
- `示意圖` 放圖片的直接網址；建議把圖片放進 GitHub repo 的 `assets/` 再取其網址，Google 雲端硬碟的分享連結常常無法顯示。
- **`單位成本` 這一欄只有後台會讀，老師端的程式碼完全不會取它**，所以投票期間不可能被看到。

**分頁二：老師**

| 姓名 | 通行碼 | 任教參賽班數 | 自訂額度 | 備註 |
|---|---|---|---|---|
| 王小明 | 4821 | 3 | | |
| 陳主任 | 5930 | 0 | 400 | 行政加給 |

- 預設額度由程式算：`250 + 50 × 任教參賽班數`。
- **`自訂額度` 有填數字，就以它為準**（空白或 0 代表用公式算）。
- 這兩欄不必手動編輯試算表，登入後台的「✨ 額度設定」分頁可以直接改、直接存。

**分頁三：訂單**（只留標題列，其餘空白）

| 時間 | 老師 | 商品ID | 售價 |
|---|---|---|---|

**分頁四：設定**

| 項目 | 設定值 |
|---|---|
| 開賣狀態 | 開賣中 |
| 活動名稱 | 誰能把禮物送進老師ㄉ心裡 |

把「開賣狀態」改成「已截止」，老師就只能看不能買，型錄仍可瀏覽。

### 2. 申請一組服務帳戶（給程式讀寫試算表用）

1. 到 Google Cloud Console 建立專案 → 啟用 **Google Sheets API** 與 **Google Drive API**。
2. 建立 **服務帳戶**，產生 **JSON 金鑰**並下載。
3. 打開那份試算表，按「共用」，把 JSON 裡的 `client_email`（長得像 `xxx@xxx.iam.gserviceaccount.com`）加為**編輯者**。

### 3. 填 secrets

在 Streamlit Cloud 的 App settings → Secrets 貼上（本機測試則存成 `.streamlit/secrets.toml`）：

```toml
sheet_url = "https://docs.google.com/spreadsheets/d/你的試算表ID/edit"
admin_password = "自己改一組"

[gcp_service_account]
type = "service_account"
project_id = "..."
private_key_id = "..."
private_key = "-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
client_email = "...@....iam.gserviceaccount.com"
client_id = "..."
auth_uri = "https://accounts.google.com/o/oauth2/auth"
token_uri = "https://oauth2.googleapis.com/token"
auth_provider_x509_cert_url = "https://www.googleapis.com/oauth2/v1/certs"
client_x509_cert_url = "..."
```

`private_key` 要整段照貼，換行保持 `\n`。

### 4. 部署

把整個資料夾推上 GitHub（**`.streamlit/secrets.toml` 千萬不要上傳**），
到 share.streamlit.io 新增 App，選 repo 與 `app.py`，貼上 secrets 即可。

## 二之二、報名資料自動上架（免複製貼上）

學生用線上報名表送出後，資料會落在同一份試算表的「**報名**」分頁（由 Apps Script 寫入，設定見「報名表_收件設定說明.md」）。商城會自動讀這張分頁：

- **「審查」欄填「通過」的班級，商品立刻出現在型錄**，不用再手動複製到「商品」分頁。
- 對應關係：班級→商品ID與班級、商品名稱→商品名稱、售價→售價、**單位總成本→單位成本**、商品介紹→商品介紹、示意圖連結→示意圖。
- 「商品」分頁仍然有效，可以放不是走報名表進來的商品（例如老師自製的示範品）；兩邊同名以報名分頁優先。
- 學生補件重送時，Apps Script 會把該班的「審查」清空，商品自動從型錄下架，等你重新審過才會再出現。

後台「📋 報名審查」分頁可以直接改審查狀態，並會自動標出**售價低於成本**、**售價不在區間**的班級，下方還能單看某一班的示意圖與報名表全文。

## 三、後台怎麼調每位老師的商貿幣

用管理密碼登入後會多出兩個分頁：

**📋 報名審查**：改審查狀態、看單班報名表與示意圖（詳見上一節）。

**🔐 後台結算**：三座冠軍、各商品的購買數量／銷售額／銷貨成本／毛利／毛利率、下載結算表、每位老師花了多少。

**✨ 額度設定**：一張可以直接編輯的表。

- 改 `任教參賽班數` → 額度自動跟著 `250 + 50 × 班數` 變動。
- 想單獨給某位老師特別額度（例如主任、實習老師、跨科支援的老師），在 `自訂額度` 填數字即可，那一位就不再吃公式。
- 最下面一列是空白列，直接打名字就能**新增老師**；`備註` 欄可以寫為什麼給這個額度，日後核銷或被問起有依據。
- 按「儲存額度設定」才會寫回試算表，老師端重新整理後生效。
- 如果把某人的額度調到比他已經花掉的還低，畫面會跳警告列出是誰，已下訂的訂單不會被自動取消，請自行處理。

## 四、丟上 GitHub 並部署到 Streamlit

### A. 建 GitHub repo

最省事的做法（不用裝 git）：

1. 到 <https://github.com/new>，Repository name 例如 `teacher-market`，**選 Private**（名單與通行碼雖然放在試算表，但保守一點比較好），按 Create。
2. 進入 repo → **Add file → Upload files**，把解壓縮後資料夾裡的 `app.py`、`requirements.txt`、`README.md`、`data/`、`assets/`、`tools/`、`.streamlit/config.toml`、`.gitignore` 全部拖進去 → Commit。
3. **`.streamlit/secrets.toml` 絕對不要上傳**（`.gitignore` 已經幫你擋，但手動拖曳會繞過它，請自己確認）。

習慣用指令的話：

```bash
cd 解壓縮後的資料夾
git init
git add .
git commit -m "教師節模擬市場商城"
git branch -M main
git remote add origin https://github.com/你的帳號/teacher-market.git
git push -u origin main
```

### B. 部署

1. 到 <https://share.streamlit.io>，用同一個 GitHub 帳號登入並授權。
2. **Create app → Deploy a public app from GitHub**（私有 repo 也可以，授權時勾選即可）。
3. 填：Repository＝剛剛那個 repo、Branch＝`main`、Main file path＝`app.py`。
4. 網址（App URL）可以自訂，例如 `ylhcvs-market`，之後老師拿到的就是 `https://ylhcvs-market.streamlit.app`。
5. 點 **Advanced settings → Secrets**，把第二節那段 toml 整段貼上 → Save。
6. 按 Deploy，約 2～3 分鐘後就上線。之後在 GitHub 改了程式碼，Streamlit 會自動重新部署。

### C. 上線後

- App 右下角的 Manage app 可以看即時 log，出錯時第一個看這裡。
- Settings → Secrets 隨時可以改管理密碼，改完 App 會自動重啟。
- 老師端建議直接發**短網址或 QR Code**，比貼一長串網址容易。

## 五之二、會不會被 Google 擋（429）

Google Sheets API 的配額是**每分鐘每專案 300 次讀取、每分鐘每使用者 60 次**，讀寫各自計算，超過會回 `429 Too many requests`。**服務帳戶算一個使用者**，所以整個商城所有老師的流量共用那 60 次／分鐘。

這份程式已經做了三件事把用量壓下來：

| 資料 | 快取時間 | 說明 |
|---|---|---|
| 商品、老師 | 120 秒 | 開賣期間幾乎不變 |
| 報名 | 90 秒 | 審查通過後最多 90 秒上架 |
| 訂單 | 20 秒 | 但**自己下訂或取消時會立刻清快取**，餘額不會慢半拍 |
| 設定 | 60 秒 | 開賣狀態切換最多 60 秒生效 |

以 30 位老師、每人每分鐘點 3 次估算，實際打到 Google 的大約**每分鐘 10～20 次**，離 60 還很遠。另外所有讀寫都包了**指數退避重試**（等 1、2、4 秒各再試一次），偶發的 429 會自己恢復，不會整頁壞掉。

線上報名表與進度看板走的是 Apps Script，**不吃 Sheets API 這組配額**，它有自己的限制（同時執行上限、每日執行時間），以十幾個班級的量完全不會碰到。

真的要更省，把上表的秒數再調大即可（在 `app.py` 各個 `@st.cache_data(ttl=...)`）。

## 六、要注意的事

- **網址是公開的**，任何人拿到都能開，所以通行碼就是門鎖，不要用 1111、0000。
- 免費主機閒置幾天會休眠，當天第一位老師開啟時要等約 30 秒。開賣前自己先點一次喚醒它。
- 取消訂單會重寫整張訂單分頁，30 人的量沒問題，但請避免多人同一秒同時取消。
- 想改**全體**的預設額度公式或售價區間，改 `app.py` 最上面的 `BASE_CREDIT`、`CREDIT_PER_CLASS`、`PRICE_MIN/MAX`；只改**某一位**老師，用後台的「✨ 額度設定」。
- 結算完按「下載結算表 CSV」，可以直接貼進成果報告。
